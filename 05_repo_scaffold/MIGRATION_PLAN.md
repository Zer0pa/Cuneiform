# Migration Plan

## Objective

Turn the cuneiform lane into a truthful control-module pack that can later
support bounded internal extraction work without upgrading the lane beyond its
evidence.

## Current Status

- shared repo-docs and GPD packs have been copied and specialized
- control-only posture is explicit
- the inherited failed governing gate is staged inside the scaffold
- no extracted code, install boundary, or smoke path exists yet

## Planned Sequence

1. Freeze the pack truth surfaces.
   - Keep the failed P5 gate and the control-only posture coherent across
     README, PRD, governance, audit, and GPD files.
2. Audit the exact source families to keep.
   - Separate cuneiform-specific benchmark logic from generic methods that
     belong elsewhere.
3. Build the path-rewrite ledger.
   - Document import, data, and filesystem assumptions that currently depend on
     the live monorepo.
4. Stage one truthful minimal rerun surface.
   - Prefer manifest validation or a tiny fixture path over a fake full rerun.
5. Re-evaluate promotion only if the underlying scientific gate is genuinely
   repaired in a future workstream.

## Migration Rules

- Do not narrate P6 or P7 diagnostics into a pass.
- Do not vendor heavy corpora or rights-limited images into this scaffold.
- Do not absorb reusable methods that belong in another lane just to make this
  lane look complete.
- Keep the handover docs frozen to the real gate state.

## Exit Criteria For The Next Stage

- source ledger complete
- data policy explicit
- at least one bounded rerun target identified
- no hidden claim that the cuneiform science gate has passed
